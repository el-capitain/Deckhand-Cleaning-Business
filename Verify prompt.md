# Coverage Verify Action

A coverage analysis tool that compares any two documents — a **source document** and a **target document** — and produces a detailed report on how thoroughly the target covers the content of the source. Finds gaps, optionally fixes them, and stores coverage metrics for traceability.

---

## What It Does

Enumerates every discrete item in the source document, maps each one to the target document, calculates a coverage percentage, and produces a structured report. Can be used to verify that any output document (a plan, a draft, a summary, a spec, a guide) faithfully and completely reflects any input document (a brief, a request, a transcript, a rubric, a source text).

---

## The Protocol

### Step 1: Enumerate Source Items

Parse the source document into a numbered list of discrete, independently verifiable items. Each item is one claim, requirement, instruction, constraint, detail, or piece of information that could be checked against the target.

Guidelines:
- One item per line, numbered sequentially
- Each item must be independently checkable
- Include both explicit statements and clear implicit constraints
- Do not interpret or combine — if something was said twice in different ways, list it twice
- Err heavily on the side of inclusion

### Step 2: Map Items to Target

For each enumerated source item, search the target document and classify its coverage:

| Status | Definition |
|--------|------------|
| **Full** | The item is clearly and sufficiently addressed in the target |
| **Partial** | The item is mentioned or touched on, but lacks detail, specificity, or context |
| **Missing** | The item does not appear in the target at all |

### Step 3: Calculate Coverage
```
Coverage % = (full + 0.5 × partial) / total × 100
```

Round to the nearest integer. This is the **pre-fix score**.

### Step 4: Fix Gaps (Optional)

If fix mode is enabled, address each missing or partial item directly in the target document:

- **Missing item?** Add it to the most logical location in the target
- **Partial item?** Expand the existing mention with the missing detail
- Keep additions proportional — don't over-engineer a simple target document
- Never invent content — only add what the source explicitly contains
- Document every change made

### Step 5: Recalculate and Store

After fixes (if applied), recalculate the coverage score. Then append the full coverage report to the target document.

## Output Report Format

Append the following section to the target document upon completion:

---

## Coverage Report

**Source document**: [name or description]  
**Target document**: [name or description]  
**Items enumerated**: [N]  
**Pre-fix coverage**: [X]% ([full] full, [partial] partial, [missing] missing)  
**Post-fix coverage**: [X]% ([N]/[N] items addressed) *(omit if fix mode not used)*

### Coverage Map

| # | Source Item | Target Location | Status |
|---|-------------|-----------------|--------|
| 1 | [Item text] | [Section or note] | Full |
| 2 | [Item text] | [Section or note] | Partial |
| 3 | [Item text] | — | Missing |
| … | … | … | … |

### Fixes Applied *(omit if fix mode not used)*

- [Description of change made and where]
- [Description of change made and where]

### Gaps Remaining

- [Any items still partial or missing after fixes, with notes on why they were not resolved]

*Generated by coverage-verify*

---

## Modes

| Mode | Behaviour |
|------|-----------|
| **Report only** | Enumerate, map, calculate, and output the coverage report. Do not modify the target. |
| **Fix + report** | Enumerate, map, calculate, fix gaps in the target, recalculate, then output the report. |

Default is **report only** unless fix mode is explicitly requested.

---

## What Not To Do

- Don't add content that isn't in the source — you're checking coverage, not expanding scope
- Don't restructure the target document — keep its existing organisation, just fill gaps
- Don't skip items because the target "looks complete" — always enumerate and map every item
- Don't merge distinct source items into one coverage entry — map them separately
- Don't invent target locations — if an item is missing, say so rather than forcing a weak match
